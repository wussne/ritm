# Ритм

Личное расписание: ученики, пары ТУСУР (435-2), вождение, заметки и поиск окон. Исходники без привязки к Sites. Ничего не опубликовано.

## Сначала посмотреть

Открой `preview.html` двойным кликом. Это автономный интерактивный просмотр, без установки и сети. Внутри — ученики со скрина и снимок настоящего расписания 21–27 сентября 2026. Можно открыть карточки, записать итоги, добавить ученика, поискать время. Изменения в просмотре сбрасываются при перезагрузке. Это **не основной рабочий сайт**, живой синхронизации в нём нет.

## База и хостинг

Выбрана **SQLite**: один файл `data/ritm.sqlite`, отдельный сервер БД и покупка MySQL не требуются. В базе — ученики, уроки, заметки, версии данных и кеш каждой недели. Используется стандартная библиотека Node.js 24, отдельный драйвер SQLite не нужен.

Нужен хостинг с **Node.js 24+ и постоянным диском**, либо VPS. Обычный тариф только с PHP/MySQL не запустит сервер. MySQL можно подключить заменой слоя хранения в `server/index.js`, но это отдельная адаптация; текущая версия его не поддерживает. GitHub Pages сам по себе не заменяет сервер для базы, Cookie и фоновых обновлений. Не покупай тариф только ради MySQL: сначала проверь Node.js и постоянный диск.

Приложение рассчитано на **одного пользователя и один процесс Node**. Несколько копий сервера могут дублировать напоминания. База и Cookie не находятся в `dist` и не раздаются посетителям.

## Запуск на Mac / Linux

Нужен Node.js 24+. В папке проекта:

```bash
npm ci
cp .env.example .env
```

В `.env` задай свой `APP_PASSWORD` (12+ символов) и случайный `SESSION_SECRET` (32+ символа). Генерация секрета:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

В двух терминалах, в папке проекта:

```bash
npm run server
```

```bash
npm run dev
```

Открой `http://127.0.0.1:5173`, войди с паролем из `.env`. Данные уже сохраняются в SQLite; это рабочий режим.

Уроки со скрина перенесены с повтором раз в неделю, начало — неделя первого запуска. **60 минут — предположение**, отмеченное в интерфейсе. Уточни длительность через «Изменить».

Выбери подгруппу А или Б в настройках. До выбора импортируются обе; занятия без указания подгруппы остаются всегда. Нераспознанные комментарии сохраняются, но автоматически не фильтруются.

## Автошкола

Скопируй значение заголовка Cookie своего авторизованного запроса в `DS_COOKIE` в `.env`, в одну строку. Можно использовать только `.AspNet.ApplicationCookie=…` — этот вариант проверен:

```dotenv
DS_COOKIE=.AspNet.ApplicationCookie=YOUR_VALUE
```

Перезапусти сервер, нажми «Обновить». Cookie не встраивается в клиентский JavaScript. Реальный токен из переписки в архив не включён. Это сессионный доступ, а не вечный API-ключ: при истечении входа нужно обновить значение. Сайт покажет ошибку источника, сохранив старое расписание.

Запрос использует `OnlyMine=true`, `timeshift=-420`, `from=<понедельник>`, `to=<следующий понедельник>`. Не пытаемся угадывать принадлежность записи по `State` или `OrderNum`. Для недели 21–27 сентября реальный запрос подтвердил 3 записи: 21.09 18:00–19:30, 23.09 15:00–16:30, 25.09 18:00–19:30.

Без `DS_COOKIE` приложение работает, но предупреждает о неполной проверке времени.

## ТУСУР: проверка недели

1. Загружается страница группы и настоящий список недель с `week_id`.
2. Нужный `week_id` выбирается по **дате понедельника**, не по арифметике чётности.
3. Загружается отдельная страница этой недели.
4. Проверяется дата **каждой** пары. Другая неделя — ошибка обновления.
5. Сохраняются ID, полное название, время, аудитория, преподаватель, подгруппа и комментарии.

Если структура сайта изменится или занятия не распознаны, старые записи не очищаются. Даже действительно пустую неделю пока нужно проверить вручную: приложение осторожно не объявляет её свободной.

## Синхронизация

- При входе и смене недели — запрос именно для выбранной недели.
- При возвращении во вкладку и каждые 15 минут — повторное обновление.
- В production сервер обновляет текущую и следующую неделю каждые 15 минут и при закрытом сайте.
- «Обновить» запускает проверку вручную.
- Для каждого источника/недели отдельно хранятся кеш, время успешного обновления и ошибка.
- Сначала показываются сохранённые данные. Успешный новый ответ целиком заменяет неделю своего источника: отменённые записи исчезают, дубли не добавляются.
- Ошибка одного источника не мешает другому и никогда не удаляет старые занятия.
- Заметки хранятся отдельно по ID события. Если источник выдаст новый ID взамен старого, заметка сама не перейдёт на новое событие.
- Браузер хранит последнюю копию для чтения при недоступном API. Изменения без связи запрещены. Полный запуск сайта с нуля без сети не обещается: service worker в этой версии нет.
- При одновременном редактировании с двух устройств вторая запись получает предупреждение о конфликте версий. Обнови страницу перед повторным сохранением.

## Время и повторы

Учитываются длительность, все занятия, перерыв между уроками и дорога до/после пар и вождения. Расчёты — **Томск (UTC+7)**, независимо от зоны устройства.

Известное пересечение/недостаток времени на дорогу блокирует сохранение. При отсутствии свежих данных нужно явно отметить согласие на сохранение с предупреждением. Неизвестная неделя не считается свободной.

Повторяющийся урок проверяется на **8 ближайших повторениях**, с учётом конечной даты. Кнопка обновления загружает каждую из этих недель. Это горизонт проверки, а не гарантия на весь учебный год. Новые конфликты видны после обновлений; приложение не переносит согласованные уроки самостоятельно.

Перенос: только одно занятие или это и последующие. Отмена одного урока создаёт исключение. Отмена будущей серии сохраняет прошлые занятия. Заметка конкретного переносимого занятия переносится вместе с ним; заметки других будущих экземпляров при замене всей серии не перераспределяются автоматически.

## Заметки

Нажми на любое событие: своя заметка, отметка подготовки, данные источника. Урок показывает текущую тему, домашку и план ученика. Карточка ученика содержит общие заметки, материалы и историю. «Итоги урока» обновляют краткую карточку и добавляют запись в историю.

**Сохранение явной кнопкой, автосохранения черновика нет.** Ссылки на материалы хранятся текстом. Загрузка файлов и кабинеты учеников не входят в версию.

## Напоминания

Необязательные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` подключают напоминания лично тебе. Создай бота, напиши ему `/start`, укажи свой chat ID. Приложение ничего не отправляет ученикам.

Проверка каждые 30 секунд. Интервал напоминания в настройках; 0 выключает его. Сервер должен работать постоянно. У отправленного напоминания есть сохранённый ключ, перенос времени создаёт новый. При ошибке Telegram сервер повторяет попытки до начала урока. Доставка не гарантируется при отключённом сервере или Telegram.

Если заданы переменные, напоминания активны и в разработке — не подключай бота в тестовой копии. Утренней сводки и Telegram-уведомлений об изменениях расписания пока нет. Пересечения после обновлений отмечаются в календаре.

## Сборка для сервера

```bash
npm ci
npm test
npm run build
npm start
```

Production требует **HTTPS**: cookie входа Secure. Для локального HTTP используй режим разработки. Сервер слушает `127.0.0.1:3001`; перед ним ставится Nginx/Caddy. Примеры — `deploy/nginx.conf`, `deploy/ritm.service`. В них нужно подставить свой домен, пути и пользователя.

Загружается серверная часть, `src/domain.js`, зависимости и `dist` — **не только `dist`**. Если собираешь локально, на сервере достаточно `npm ci --omit=dev`. Папка `data` должна переживать пересборки и перезапуски. Docker-конфигурация не включена.

## Резервная копия

В настройках есть экспорт JSON (ученики, заметки, расписание). Это читаемый экспорт, не автоматический импорт.

Для полного восстановления: останови приложение, скопируй **всю папку `data`**, запусти обратно. Восстановление — с остановленным сервером заменить `data` своей копией и запустить. Не копируй только основной файл SQLite во время активной записи WAL. `.env` резервируй отдельно и не публикуй в Git.

## Проверки и ограничения

- Production-сборка проходит.
- Тесты: недели, переход года, повторы/отмены, полночь, буферы, подгруппы, неизвестные недели, парсеры, API-вход, сохранение, версии и валидация.
- DOM-тесты React: создание ученика, запись итогов/истории, блокировка пересечения, длительность 90 минут при выборе окна.
- Реальный ТУСУР: недели 21–27.09 и 28.09–04.10.2026 (4 чётная и 5 нечётная), по 19 записей с проверкой дат.
- Реальный DSControl `OnlyMine=true`: 3 личные записи вместо 8 общего списка.
- **Визуальный браузерный просмотр не выполнен:** среда заблокировала локальный сервер. DOM-тесты не заменяют проверку размеров и внешнего вида. Перед постоянным использованием открой `preview.html`, затем рабочий сайт на ноутбуке и телефоне.
- Реальное сообщение Telegram не отправлялось: бот не предоставлен.
